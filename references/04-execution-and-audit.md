# 执行、次数与验收

## 单图任务单

```json
{
  "item_id": "Pxxx",
  "sku": "source-confirmed-sku",
  "view": "back",
  "target": {"path": "absolute-current-path", "sha256": "verified-hash", "selection_reason": "owner-specified-version"},
  "references": [{"path": "absolute-reference", "sha256": "verified-hash", "role": "wrinkles-only", "excluded_roles": ["camera", "shape", "background"]}],
  "edits": ["exact-local-change"],
  "protected": ["upper-panel", "entire-puller", "width"],
  "allowed_residuals": ["owner-accepted-near-white"],
  "authorization_round": "owner-decision-id",
  "max_attempts": 3,
  "attempts_used": 0,
  "state": "ready-not-executed"
}
```

这是字段示例，不是固定每图三次授权。真实次数来自当前用户决定；任务单不会自行授权生成。输入哈希、引用顺序、实际提示词、输出路径、工具状态与尝试序号要可追溯。批量时每个SKU/图片独占自己的目标与输出目录，避免共用可覆盖文件名。

## 执行前检查

1. 第一张是否正确的初修图/指定候选？是否被误换成raw、旧main、聊天缩略截图或别SKU？
2. 单图新限制是否覆盖旧规则？如只去纸的任务不转视角、功能卡保字任务不套匿名。
3. “只动”与“保持”有没有自相矛盾？正视与斜视是否并列、匿名是否会误伤RFID？
4. 必要引用是否齐全且角色明确？没有必要就不多传。
5. 操作是否已授权、预算是否还有余额？批量委派不能创造新额度。

独立子代理只在用户/生效指令允许时使用。可按独立SKU编辑、另一代理只读审计；不得多个编辑者同时写同一图。主执行者仍需汇总核验，不能把代理的PASS当最终事实。

提示词及脚本中的每个动作应能追溯到当前要求、有效项目规则，或明确标为未执行的建议；不能把模型补充的“优化”当用户指令。修正拉链走向不授权加长拉链/拉片，恢复皮纹不授权改变已经通过的提手。用户指出越界时先冻结执行、核对实际动作来源，澄清后才按新口径继续。

## 每次之后

先封存该次原始输出与实际调用记录，再判断。若用户指定“全部生成完后统一审计”，期间只做文件完整性/工具错误记录，按要求最后审计，不修完一张又反复改另一张。

一个生成失败/超时可能已经产生结果或外部成本，状态不明不能当零次无限重试。先查询已有输出或记录未知，不虚构成功。改提示词版本不重置次数；新一轮必须有新明确授权，上一轮记录不覆盖。

重复失败优先改变方法而不是增加形容词：
- 锚点总移动 → 正确原图+干净标注/明确接缝关系，不循环喂错误候选。
- 纯背景/码问题 → 授权局部处理，不整包生成。
- 精确比例总达不到 → 报实际测量，提议脚本；获准后再做。
- 材质总改变/缺隐藏面 → 补真实参考或接受合理限制，不靠新生成皮纹蒙混。

## 验收顺序与判据

| 层 | 看什么 | 不能替代它的证据 |
|---|---|---|
| 身份 | SKU、颜色、可见面、开合、口袋/面片 | 文件名、模型说同款 |
| 结构 | 带根、缝口、前后遮挡、五金、端部完整 | 只是有阴影或没X片 |
| 整体形态 | 正常支撑、比例、侧深、角部、机位 | 仅轮廓平滑或warp数学有效 |
| 材质 | 同尺度原拍纹理、原光泽、细缝 | 高清、锐利、合理新皮纹 |
| 本次目标 | 已点名缺陷是否真正消失 | 提示词写了、工具完成 |
| 非目标保护 | 已去包装/匿名/正确配件没倒退 | 蒙版外像素保护但蒙版里乱了 |
| 技术交付 | 实际尺寸、模式、背景、边缘、阴影、完整性 | 四角白、1536方图 |
| 用户选择 | 当前有效决定与确切版本绑定 | 旧状态页、历史自动评分 |

使用同尺度全图加关键局部：带根/卡窗/拉片100%查看，缩到网站实际展示大小检查识别度与整体。过度放大才可见的一点字，用户已容忍就不自动重做；结构变款不能靠缩略图掩盖。

状态至少区分：`not_run`、`candidate`、`review_pass`、`owner_accepted`、`published_verified`、`retired`、`blocked`。这些是当前投影，不改写旧事件。内容通过、背景/尺寸通过、用户接受、线上同步分别记录，避免“历史待复核组已通过”被误读为全部已上线。

## 缺陷闭合与反证门槛

执行[完整反证审计](11-first-principles-adversarial-audit.md#6-对抗式审计尝试推翻自己的通过)：每个点名缺陷建立“位置/现象/依据→目标→候选观察→新增问题”记录，先不看修复者的PASS标签，再核具体目标。复验全景、整套、100%局部和实际展示尺度。

错图/错版本、目标仍明显失败、换皮纹、损结构、文字被扭曲、新增白晕/假皱或超出“只改”范围，不能靠其他通过项抵消。没有实看关键区域，记录待验证。反向核验真实透视、功能字、圆角和用户接受例外，避免为了挑错而制造问题。

最新本轮精确次数优先于历史大额度。连续无进展时按本轮约定报告具体卡点和替代方法，不换代理归零。文件哈希改变、技术探针成功或仅非目标区域不变，都不是指定形态已修正的证明。

## 对抗式审计提问

- 我是否只盯着修复点，没发现另一边新增扎带、铭牌新字或少了拉片？
- 这幅是原来的背面，还是被改成更好看的正面？
- 两根带真从缝内出来了吗？有没有旧下垂环残条？
- 内外框都修正了吗，还是只把纸变白？
- 看上去变矮是否仅整包缩小或加宽？上半、五金是否被压了？
- 皮纹是否由细变粗、变规整，或全部褶皱被抹掉？
- 白底检查覆盖原照片区域和真孔了吗？是不是误删白产品？
- 与最新用户例外冲突的失败理由是否仍在自动执行？
- 当前文件是否确实为展示给用户的那一版，而非同名另一图？

审计不含自动修复权限。每条缺陷给位置、影响和针对性下一步；未观察到问题不要追加“优化”。

## 只读探针

依赖Pillow，在已安装它的Python运行：

```powershell
python scripts/image_probe.py "C:/absolute/final.png"
python scripts/image_probe.py "C:/absolute/final.png" --background-box 0,0,80,80 --background-box 1400,0,1536,80
python scripts/image_probe.py "C:/absolute/padded.png" --padding-source "C:/absolute/native.png" --offset 141,141
python scripts/image_probe.py "C:/absolute/edited.png" --compare "C:/absolute/source.png" --protected-box 0,0,1254,645
```

框坐标为左、上、右、下，右/下不含。背景框须人工确认不含产品、阴影、过渡。程序检查只覆盖给定区域，不推断全背景；使用明确背景mask可扩大范围。若source/destination颜色模式不匹配，不能声称字节/像素原样。Alpha应明确处理，不悄悄把透明当白。

探针schema v2比较解码RGBA8像素，并要求ICC/gamma/sRGB/chromaticity/EXIF方向等渲染元数据一致；P模式会展开调色板和透明度，不能只比较索引。它不做ICC色彩转换、不保证显示器颜色匹配；文件字节一致另看SHA256。像素检查仅支持`1/L/LA/P/RGB/RGBA`，高位深、浮点、CMYK等只允许读取元数据，不能悄悄降位后宣称精确保留。坐标基于原存储栅格，不自动按EXIF转图。

局部缩放额外报告公式：目标H=基线H×r；固定点、实际旧/新底、宽度、整个拉片保护范围。为保护下垂五金，变形起点可在拉片以下，但仍应证明拉链到底总高度达到目标。邻接两行/边缘/阴影需要视觉检查，像素证明不自动证明自然衔接。
