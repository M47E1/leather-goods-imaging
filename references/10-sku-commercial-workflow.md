# SKU商业图：整套比较、分流与验收

适用于主辅图统一、逐图审查、训练案例总结及批量修复。客户的尺寸、文字例外、阴影容忍和暂停品类来自项目配置，不复制其他客户的约定。各项目应另读其当前有效配置和逐图决定。

具体几何目标、测量边界、厚筋/锯齿、颜色诊断、贴地阴影和反证步骤统一读[第一性原理与对抗审计](11-first-principles-adversarial-audit.md)。本章组织整套工作，新章展开每个检查项；不只执行“去字/去包装/方画布”三项。

## 1. 先锁图片，再比较整套

每张绑定SKU、颜色变体、可见面、开合状态、主/辅位置、media或唯一资产ID、文件路径、SHA256、有效选版依据。候选较新不等于已选用；原拍、现用图、待验候选、退役图分开。

先读现用清单和当前检查点，按一套图并排看原文件，再放大关键区域。网页正方形容器、缩略图和CSS滤镜不能代表原文件合格。带编号截图能帮助定位，不能替代底图身份核对。

同SKU同色的主图只提供已合格的颜色、主体尺度或自然支撑参照；发现主图自身缺陷也指出。原拍及确认资料提供结构/材质事实。不要反向缩主图、调淡主图以迁就不合格辅图。

## 2. 检查应回答什么

| 维度 | 必须比较的对象 | 常见误判 |
|---|---|---|
| 颜色/鲜艳度/对比度 | 同色同SKU对应面片、黑位层次、光泽；多色拼片分别比较 | 每张单看都还行；彩片提鲜艳度时把白/灰/黑染色；黑包一味加饱和度 |
| 材质保真 | 与同款同色可信原拍的对应皮面比较细纹尺度、褶皱、毛孔及光泽 | 轮廓更整齐就接受新皮纹；把锐化颗粒、生成纹理当真实材料 |
| 主体占幅 | 排除伸出的带、提手、挂件后，包身高度、轮廓面积、重心与留白 | 只量物体最大外框；方图就判大小合格；缩主图迁就小辅图 |
| 包体比例 | 同款同视图的真实长宽、厚度与支撑 | 将侧面拉宽成正面；将展开内页压成闭合钱包 |
| 形态/畸变 | 外框、内框、前袋、拉链轨、拼接线、扣带、底边、铭牌及口金 | 只顺外沿，内部仍歪；抹平天然皮纹；把设计弧线拉直 |
| 背景/阴影 | 原照片内部与补边、确认为背景的带间空隙；真实接触、光向与渐变 | 只测四角；灰白矩形当自然阴影；全图阈值抹白 |
| 包装/文字/五金 | 包装与真带区别；小牌、侧牌、小拉片、压印、反光区 | 只看大铭牌；删实体牌/拉片；把旧客户文字例外带入新项目 |
| 视角/用途 | 正背侧、内部、细节；三分之四的侧转与俯视程度 | 背图变正面；移动画布冒充改机位；所有图改三分之四 |

占幅不能机械统一数值：同SKU相近整体图先相互比较，同类闭合钱包再跨SKU比较；保留包型和视角差异。可标记粗略包身框辅助说明，但粗框不是精确分割、面积真值或物理尺寸。未经校准的阈值不得自动判视觉合格。

人工校准同时界定“不用修”的范围：位于可接受占幅上限的图不再放大；轻微、自然且不影响展示的凹陷不为追求矩形而自动重画。明确获准保留的珠链/铭牌字不能归入通用去吊牌/匿名模块；用户说“只调大小”时，其他观察不进入执行指令。

### 三层看图尺度：整套 → 全景 → 原像素局部

| 层级 | 怎样看 | 必须回答的问题 |
|---|---|---|
| 整套比较 | 全部现用图放入同尺寸画布展示框，保留各图原占幅，不把每个包自动缩放成等大；比较相应颜色、视图与开合状态 | 主辅图包身高度、宽度、轮廓面积和重心是否协调？颜色、鲜艳度、黑位与材质风格是否成套？同类钱包间是否明显忽大忽小？ |
| 单张全景 | 看完整原图，并与对应底图/参照并排；不只看局部截图 | 外框与内框是否同时协调？左右侧边、叠层、底边、前袋、拉链和扣带是否歪斜、鼓胀或偏移？正视是否带明显仰视？影子是否让产品落地？ |
| 原文件100%局部 | 检查皮面、每层拉链及两端、内外框交点、牌/扣具、过亮与过暗处、包底接触带；跨图材质比较对齐同部位和相近实体范围 | 是否重画细纹、磨成塑料、亮部截白或暗部丢失细节？拉链问题在齿轨还是布带？五金是否被拉弯？阴影与落点是否分离？ |

100%指原文件像素查看，不是网页缩略图放大。必要时200%只辅助定位边界，不将插值产生的纹理当新证据。修复候选先查目标局部，再回看单张全景与整套；局部更直但整体变形、包身忽大忽小或材质失真，仍不能通过。

### 容易漏检的判定边界

- **形态看内外及层次。** 外轮廓直不代表内窗/前袋/拉链也直。分清齿轨弯曲、浅色拉链布鼓出与侧边突出，指明哪一层、哪一端需要收拢，不笼统要求“整包变方”。正视应有的直线可扶正；三分之四透视、真实圆角、设计不对称与轻微自然起伏不机械拉成屏幕上的矩形。
- **曝光与饱和度分开。** 黑包正面看不清，先判断黑位/曝光，不盲目增加饱和度；局部刺眼高光先局部处理，不压暗整个包。已截白区域没有的皮纹不能靠调暗宣称恢复。
- **阴影看接触，而不只看有无。** 检查底边接触处、投影起点、方向、软硬、范围和亮暗过渡；一团灰色椭圆不自动算自然阴影。按项目约定可接受的“仅缺阴影”与已存在的悬浮/断开/脏块分开判断。
- **材质不让位于整齐。** 从原拍补材质要匹配同款同色、对应部位和透视；不能整片铺通用纹理，不能把已经完成的去包装/构图回退。原像素几何处理也会扭曲细纹或五金；即使保护区外像素没变，改动区仍须检查，刚性牌/扣不能随软皮被拉长、变弯。
- **差异不等于错误。** 同SKU颜色变体原拍就有高矮差时，先排查机位、支撑状态与产品依据；不能为占幅统一任意拉长。明确被接受的版本或轻微差异保留，不因这一轮规则更新自动重新返修。

## 3. 四条处理路线

| 路线 | 进入条件 | 应交付什么 |
|---|---|---|
| `keep` 保留 | 本轮要求下内容、构图和技术均合格，或对应版本有明确接受例外 | 简要通过依据，不加无意义优化 |
| `script` 技术/构图整理 | 包体内容可保留，仅需画布、等比占幅/居中、明确外部背景等可控处理 | 精确对象、算法范围、参照与保护区；不写整包生图提示词 |
| `edit` 局部内容修图 | 有需修复的颜色、形态、包装、文字、局部材质表现等可见问题，且底图足够可靠 | 位置、观察、依据、动作、保留项与展开后的提示词 |
| `source` 更换原图 | 裁断关键结构、严重失焦或缺失信息，不能可靠修复 | 指明缺什么源图；有可靠底图后才可执行的条件式提示词，不伪造恢复 |

“不合格”可包含仅技术未达标，必须同时列内容判断、交付判断和路线，不能让用户误以为全部需要重新生成。读不到图或文字无法辨读时明确未验证；不要为凑二元表格默认通过或捏造字词。

脚本执行仍依用户授权和平台图像工具要求。普通脚本路线只做等比缩放/补白/明确背景处理，不顺手改包体长宽、视角、颜色或结构；局部变形必须有该图的独立指示。保留真实部件，裁切前确认不会产生断口。仅为改文件画幅，不应调用生成模型。

若用户另行允许原像素调色，结构合格且仅颜色/曝光不一致的图可走脚本路线：使用受控颜色/亮度/对比度变换，保护纹理及非目标区域，不把“颜色问题”自动等同于重新生图。记录调色范围和参考；高光中已丢失的细节不得冒充被恢复，也不借调色修改颜色变体。

已有全库技术问题清单就续用：到本SKU具体图号时按资产ID/哈希核对。源文件变化只复验变化项，不反复全库扫描，也不把历史固定数量写进通用规则。

## 4. 逐图记录与提示词

问题必须至少有：`编号、SKU、media/资产ID、内容判断、交付判断、路线、位置、观察、依据、动作、参照及其作用、未知、底图路径/哈希`。不要只写“统一风格”“加强质感”“大小不对”。

### 内容修图模板

```text
目标：[编号] / SKU [值] / [颜色、可见面、开合状态、主辅角色]。
唯一编辑底图：[准确文件及哈希]。其他引用不得替代这张图。
参照：[同SKU主图/同款原拍]，仅用于[色调/包身尺度/已知结构/自然支撑]；不复制其机位、缺陷或包装。

实际问题及动作：
1. [具体部位]目前[可见现象]，依据[本图/同款具体参照]，只调整为[方向和程度]。
2. [其他确实存在的问题]。非问题不追加动作。

保留：产品身份、原可见面、开合、连接、五金款式、口袋/卡槽与面片数量、缝线布局、真实材料纹理。
本次允许改变的颜色/几何仅限上面的动作；其余保持。不镜像、不补造未见结构、不从旧参考带回已依有效规则去除的包装或文字；若本次明确纠正误删并授权恢复指定文字，则以可信带字源恢复，保护其他已完成修复，不猜写字词。
主体尺度：[包身参照和方向]，不是带/提手最大外框；[局部近景或展开内页的用途例外]。
文字和包装：[按当前项目及单图规则展开，明确作用区域和保留实体]。
输出：[项目画布比例及像素]，不以拉伸产品填画布。背景与阴影：[项目标准及容忍]。
验收：[本图缺陷消失、非目标未倒退、整套一致性、实际文件检查]。
```

### 脚本整理模板

```text
对象：[编号/资产ID/准确底图与哈希]。包体内容可保留，不调用生成。
仅执行：[等比缩放/补白/居中/明确外部背景区域校正]。
主体参照：[同SKU指定图/同类钱包/本图既有构图]；需要变化的量应从本图测量或按已批准数值计算，不套案例百分比。
保护：[包体、白色产品、展示纸、窗膜、五金、完整带端、边缘过渡、自然阴影]。
输出：[实际画布尺寸、模式、独立候选路径]；不覆盖原拍或现用图。
验收：读取实际宽高并解码，检查合成边界与完整性；按处理方式验证保护区/等比几何，再与整套并排比较。
```

提示词组装时按动作展开[已有模块库](02-prompt-library.md)，不要让“颜色不变”与“匹配主图颜色”、或“机位不动”与“降低俯视”同时出现。功能字保留模块仅在当前有效决定要求保留时使用，不能压过更新的项目文字规则。

## 5. 验收与可见交付

- 技术层：实际解码尺寸、比例、模式/方向、身份与哈希、链接；背景只对确认区域测量。输出写了目标尺寸，不算实测。
- 视觉层：原图全景＋关键局部＋同SKU同尺度并排；钱包等相近整体图补跨SKU比较。重点复查本次修复、相邻结构及已通过部分有没有倒退。
- 状态层：评审通过、用户选中、实际修复、上线读回、缓存退役分开。不把“这套方法不错”理解为所有图都已验收或获准发布。
- 交付层：展示全部受审图片，不只挑几个案例。每张显示判断与路线，问题和动作可读，提示词可复制；页面保留原文件表现，不用裁切/滤镜伪装一致。
- 技术已达标而视觉不合格不能通过；内容已好、仅输出尺寸偏差，按授权脚本收尾，不循环重画整包。
- 原始评审与生成事实不覆盖；摘要/页面是读取投影。后续推翻判断追加更正，不能改写原始证据或悄悄将待验候选设为现用。

复盘抽查时，按准确资产去重区分：抽中图片自身的质量问题、仅要求删除的图片、用作参照但实际问题在同SKU其他图片、原先已知未解决项。同图多个缺陷/多次返修仍算一张，追加的整套任务不塞回样本分母；没点名不等于本次验证通过，历史发现数量也不等于当前未完成数量。分层抽样或刻意纳入难例的结果不能当全库不合格率。

## 6. 从指导案例推广，而不是宣称模型已训练

从用户逐图指导中抽取“现象—参照—动作—保护项—验收—例外”。先用一组不同SKU验证能否自己发现相同类型问题，再按实际授权修复。训练案例是规则和样例，不是模型权重训练；接触过的SKU不是盲测。

可直接检验方法的情境：
- 主图包身大，背图很小，但两张都是方图：不是画布问题；先判背图内容，合格则等比构图脚本，不缩主图迁就。
- 彩色辅图发灰、内框歪：逐面片匹配主图，修内外框；不只去字，不给黑白面片染色。
- 横幅细节图内容清晰且用途正确：按项目要求整理画幅，不复制主图角度和包身占幅。
- 长带原图被切断：不能补白让断口悬空，更不能想象带连接；找完整源图。
- 用户只允许补白：即使发现其他问题也只报告，不扩成颜色/形态重修。
- 主图有包装、辅图无包装：主图仅供合格的色调/尺度；不能把包装复制回辅图。
